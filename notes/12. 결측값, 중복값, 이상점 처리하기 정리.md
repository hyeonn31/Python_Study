## 1. 결측값 (Missing Value)

값이 비어 있는 칸. pandas에서는 `NaN`으로 표시된다.

### 결측값 찾기

```python
airbnb_df.info()
```

```
 5   rating         700 non-null    float64
```

전체 713줄인데 `rating`만 700이다. 13개가 비어 있다.

```python
airbnb_df.isna()   # 결측값이면 True, 아니면 False
```

`isna()`는 표 전체를 True/False로 바꿔서 보여 준다. 이것만 보면 713줄이라 뭐가 어디 있는지 모르니까 보통 뒤에 뭘 더 붙여서 쓴다.

```python
airbnb_df.isna().sum()
```

```
id                0
state             0
...
rating           13
...
```

**열마다 결측값 개수**가 나온다. True는 1, False는 0으로 계산되니까 더하면 True의 개수 = 결측값 개수가 된다.
결측값 확인할 때 제일 많이 쓰는 코드다.

#### NA가 뭐야?

**Not Available**(값을 구할 수 없음)의 줄임말이다. R이라는 통계 언어에서 결측값을 `NA`라고 부르는데, pandas가 R을 본떠 만들어지면서 이름도 따라왔다.

- `NaN`은 **Not a Number**. 원래는 0/0처럼 숫자가 아닌 계산 결과를 뜻하는데, pandas는 빈 값을 이걸로 표시한다.
- `isnull()`도 `isna()`랑 완전히 같은 함수다. 처음엔 `isnull`만 있었는데 R이랑 이름을 맞추려고 `isna`가 추가됐다.

### 결측값이 있는 행만 보기

```python
airbnb_df.isna().any(axis=1)
```

```
0      False
1       True
2      False
...
```

**행마다** 결측값이 하나라도 있는지 알려 준다. `any()`는 "하나라도 True면 True"라는 뜻.

여기서 `axis=1`이 헷갈렸다.

| | 훑는 방향 | 결과 | 질문 |
|---|---|---|---|
| `any(axis=0)` (기본값) | 위 → 아래 | **열마다** 하나 | 이 열에 결측값 있어? |
| `any(axis=1)` | 왼 → 오른쪽 | **행마다** 하나 | 이 행에 결측값 있어? |

`axis=1`은 "열"이라고 외웠는데, 집계 함수에서는 **열 방향으로 훑어서 행마다 결과를 낸다**고 생각해야 맞다.
`axis=0`으로 해도 에러는 안 나지만 결과가 열 이름별로 나와서, 아래처럼 행을 고르는 데는 못 쓴다.

```python
airbnb_df[airbnb_df.isna().any(axis=1)]
```

불린 인덱싱으로 결측값이 있는 행만 뽑았다. 13줄이 나오는데, 전부 `n_reviews`가 0이다.
**리뷰가 하나도 없어서 평점이 비어 있는 거였다.** 결측값이 왜 생겼는지 보면 어떻게 채울지 감이 온다.

### 처리 방법 1: 지우기 — dropna()

```python
airbnb_df.dropna()
```

결측값이 하나라도 있는 **행을 통째로 삭제**한다. 713 → 700줄.
간단하지만 데이터가 줄어든다. 결측값이 많으면 쓰기 곤란하다.

`dropna(axis=1)`이면 결측값이 있는 **열**을 삭제한다. 여기서 하면 `rating` 열이 통째로 날아간다.

`dropna()`도 결과만 보여 주고 원본은 그대로다. 노트북에서도 실행만 하고 저장은 안 했다.

### 처리 방법 2: 채우기 — fillna()

이번엔 평점 평균으로 채웠다.

```python
airbnb_df['rating'].mean()            # 94.82
airbnb_mean = airbnb_df['rating'].mean().round(0)   # 95.0

airbnb_df['rating'].fillna(airbnb_mean)
```

- `mean()`은 결측값을 **빼고** 평균을 낸다. 700개로 평균을 낸 것.
- `round(0)`은 소수점 없이 반올림. 평점이 96, 100, 75처럼 정수라서 맞춰 줬다. `round(1)`이면 소수점 첫째 자리까지(94.8).

`fillna()` 결과를 출력했는데 95가 안 보여서 안 된 줄 알았다. 결측값이 있는 행이 출력의 `...`(생략된 가운데) 안에 숨어 있었던 것.

#### mask로 채워졌는지 확인하기

```python
mask = airbnb_df['rating'].isna()
airbnb_df['rating'].fillna(airbnb_mean)[mask]
```

```
1      95.0
127    95.0
189    95.0
...
632    95.0
```

13개 전부 95로 채워진 게 보인다. 단계별로 보면

1. `mask`: 결측값 자리가 True인 시리즈
2. `fillna(airbnb_mean)`: 결측값을 95로 채운 **새** 시리즈 (원본은 그대로)
3. `[mask]`: 2번에서 mask가 True인 자리, 즉 **원래 비어 있던 자리만** 골라냄

`[mask]`는 불린 인덱싱이다. 위치는 순서가 아니라 **인덱스 번호**로 맞춘다. 둘 다 같은 원본에서 나왔으니 인덱스가 똑같아서 제자리끼리 짝이 맞는다.

**주의: mask는 원본을 채우기 전에 만들어야 한다.** 원본을 먼저 덮어쓰면 결측값이 없어져서 mask가 전부 False가 되고, 결과가 텅 빈 `Series([])`로 나온다. (스마트폰 실습에서 실제로 이렇게 됐다.)

#### 원본에 저장

```python
airbnb_df['rating'] = airbnb_df['rating'].fillna(airbnb_mean)
airbnb_df.isna().sum()   # rating 0
```

`fillna()`도 결과만 돌려주니까 열에 다시 넣어야 반영된다.

### 셀 실행 순서 때문에 헤맨 것

평균을 `round(1)`로 바꿔서 94.8로 다시 채우려고 했는데, 결과에 계속 **94.82**가 그대로 남아 있었다.

1. 그 전에 반올림 안 한 평균(94.82)으로 **원본을 이미 채워 버린** 상태였다.
2. 원본에 결측값이 더 이상 없으니까, 새로 `fillna(94.8)`을 해도 채울 자리가 없다.
3. 그래서 아무것도 안 바뀌었다.

노트북은 셀을 **실행한 순서대로** 결과가 쌓인다. 원본을 덮어쓰는 셀이 있으면, 다시 할 땐 `read_csv` 셀부터 순서대로 다시 실행해야 한다.

## 2. 중복값 (Duplicate)

똑같은 데이터가 두 번 이상 들어간 것.

### 중복값 찾기 — duplicated()

```python
airbnb_df.duplicated()        # 중복이면 True
airbnb_df.duplicated().sum()  # 2
airbnb_df[airbnb_df.duplicated()]
```

```
         id          state  ...  price
493  UD8253  MASSACHUSETTS  ...    124
496  UD8253  MASSACHUSETTS  ...    124
```

**처음 나온 행은 False, 두 번째부터 True**다. 그래서 `UD8253`이 사실 3번(201, 493, 496) 들어가 있는데, 첫 번째인 201번은 안 나오고 493, 496번만 나온다.
기본은 **모든 열의 값이 다 똑같아야** 중복으로 본다.

### 특정 열만 기준으로 — subset

```python
airbnb_df[airbnb_df.duplicated(subset='id')]   # 6줄
```

`id`만 같으면 다른 열이 달라도 중복으로 본다.
모든 열 기준으로는 2개였는데 `id` 기준으로는 6개다. 같은 숙소인데 평점이나 리뷰 수가 다르게 들어간 행들이 있었다는 뜻.

```
  id       rating  n_reviews
LN3479      96.0         15    ← 6번 행
LN3479      98.0         19    ← 448번 행
LN3479      99.0         25    ← 452번 행
```

같은 숙소를 시간 차이를 두고 여러 번 수집한 것 같다. 리뷰 수가 15 → 19 → 25로 늘어나 있다.

### 어떤 걸 원본으로 칠지 — keep

| `keep` | 의미 |
|---|---|
| `'first'` (기본값) | 첫 번째는 남기고, 그다음부터 중복(True) |
| `'last'` | 마지막만 남기고, 앞의 것들을 중복(True) |
| `False` | 같은 것끼리 **전부** 중복(True) |

```python
airbnb_df[airbnb_df.duplicated(subset='id', keep=False)]   # 10줄
```

`keep=False`는 짝까지 전부 보여 줘서, 중복된 데이터를 나란히 비교할 때 좋다. 6줄이 아니라 10줄이 나오는 건 첫 번째 행들(6, 201, 273, 541번)까지 포함돼서다.

### 중복값 지우기 — drop_duplicates()

```python
airbnb_df.drop_duplicates()                # 모든 열 기준 → 711줄
airbnb_df.drop_duplicates(subset='id')     # id 기준 → 707줄
airbnb_df = airbnb_df.drop_duplicates(subset='id', keep='last')
```

`duplicated()`로 찾고, `drop_duplicates()`로 지운다. `isna()` / `dropna()` 관계랑 똑같다.
옵션(`subset`, `keep`)도 `duplicated()`랑 똑같이 쓴다.

마지막에 `keep='last'`를 쓴 건, **나중에 수집한 데이터가 더 최신**이라서다. 리뷰 수가 제일 많은 행이 남는다.

```python
airbnb_df.duplicated(subset='id').sum()   # 0
```

지우고 나서 다시 세서 0인지 확인했다.

### 행을 지우면 인덱스에 구멍이 생긴다

중복을 지운 뒤에 출력해 보면 인덱스가 0, 2, 3...처럼 중간 번호가 빠져 있다. pandas는 행을 지워도 **남은 행의 번호를 다시 매기지 않는다.**
처음엔 1번 행이 사라져서 `fillna`가 뭘 잘못한 줄 알았는데, 앞에서 행을 지워서 생긴 구멍이었다. 출력 맨 아래 `Length`(실제 행 수)와 마지막 인덱스 번호가 다르면 이 경우다.

```python
airbnb_df = airbnb_df.reset_index(drop=True)   # 0부터 다시 번호 매기기
```

## 3. 이상점 (Outlier)

다른 값들과 동떨어지게 크거나 작은 값.
`price`를 보면 대부분 100~140 정도인데, 최댓값이 **1800**이다. 평균(121)을 혼자 끌어올린다.

### IQR로 정상 범위 정하기

"얼마나 튀어야 이상점이냐"를 정하는 기준이 필요한데, 많이 쓰는 게 **IQR 방법**이다. 박스플롯(7번 단원)에서 수염 밖에 찍히는 점들이 바로 이 기준으로 정해진 이상점이다.

```python
q1 = airbnb_df['price'].quantile(0.25)   # 98
q3 = airbnb_df['price'].quantile(0.75)   # 139
iqr = q3 - q1                            # 41

lower_limit = q1 - 1.5 * iqr   # 36.5
upper_limit = q3 + 1.5 * iqr   # 200.5
```

단계별로 보면

1. **`quantile()`**: 값을 작은 순서로 줄 세웠을 때 해당 위치의 값.
   - `quantile(0.25)` = Q1 (아래에서 25%)
   - `quantile(0.5)` = 중간값 (`median()`이랑 같음)
   - `quantile(0.75)` = Q3 (아래에서 75%)
2. **IQR** = Q3 − Q1. 가운데 50%의 데이터가 퍼져 있는 폭이다.
3. **정상 범위** = Q1 − 1.5×IQR 부터 Q3 + 1.5×IQR 까지. 이 밖에 있으면 이상점.

평균과 표준편차 대신 사분위수를 쓰는 이유: 평균은 1800 같은 이상점에 끌려가지만, Q1·Q3는 순서로 정해지는 값이라 이상점이 있어도 거의 안 흔들린다.

### 이상점 찾기

```python
airbnb_df[airbnb_df['price'] < lower_limit]   # 너무 싼 것: 14달러짜리 2개
airbnb_df[airbnb_df['price'] > upper_limit]   # 너무 비싼 것
airbnb_df[(airbnb_df['price'] < lower_limit) | (airbnb_df['price'] > upper_limit)]
```

"너무 싸**거나** 너무 비싼" 거니까 `|`(또는)로 연결한다. 한 숙소가 동시에 너무 싸고 너무 비쌀 수는 없으니 `&`를 쓰면 0개가 나온다.
한 줄로 쓸 때는 조건마다 괄호 필수. (11번 단원에서 정리)

### 이상점 지우기

지우는 게 아니라 **정상 범위 안에 있는 것만 남기는** 방식으로 했다.

```python
# 정상범위
condition1 = airbnb_df['price'] >= lower_limit
condition2 = airbnb_df['price'] <= upper_limit

airbnb_df[condition1 & condition2]
```

이번엔 "하한 이상 **그리고** 상한 이하"니까 `&`다. 찾을 때는 `|`, 남길 때는 `&`. 반대가 된다.

노트북에서는 결과만 보고 저장은 안 했다. 실제로 쓰려면

```python
airbnb_df = airbnb_df[condition1 & condition2]
```

스마트폰 실습 3에서 이 저장을 빼먹어서, 이상점이 안 지워진 상태로 제출할 뻔했다.

### 이상점이라고 무조건 지우면 안 된다

1800달러짜리 숙소는 샌프란시스코의 큰 집, 1794달러짜리는 말리부의 16인용 빌라였다. 입력 실수가 아니라 **진짜 비싼 숙소**다.
그래서 이상점은 일단 찾아서 눈으로 보고, 실수인지 진짜인지 판단한 다음에 지울지 정해야 한다. 이번엔 "일반적인 숙소 가격을 분석한다"는 목적이라 범위 밖을 뺐다.

## 스마트폰 실습에서 배운 것

### 결측값은 문제 상황에 맞는 값으로

`weight`가 비어 있는 3줄은 전부 iPhone 13 mini(128/256/512GB)였다.
"모델명이 같으면 무게가 같다"는 조건이 있어서, 평균이 아니라 표에 나온 실제 무게 **140g**으로 채웠다. 평균으로 채우는 게 항상 정답은 아니다.

```python
cellphone_df = cellphone_df.drop_duplicates()
```

## 한눈에 보기

| 하고 싶은 것 | 코드 |
|---|---|
| 열마다 결측값 개수 | `df.isna().sum()` |
| 결측값이 있는 행만 보기 | `df[df.isna().any(axis=1)]` |
| 결측값 있는 행 지우기 | `df.dropna()` |
| 결측값 채우기 | `df['열'].fillna(값)` |
| 채워질 자리만 확인 | `df['열'].fillna(값)[df['열'].isna()]` |
| 중복 개수 | `df.duplicated().sum()` |
| 특정 열 기준 중복 | `df.duplicated(subset='열')` |
| 중복 전부 보기 | `df[df.duplicated(subset='열', keep=False)]` |
| 중복 지우기 | `df.drop_duplicates(subset='열', keep='last')` |
| 인덱스 다시 매기기 | `df.reset_index(drop=True)` |
| 사분위수 | `df['열'].quantile(0.25)` |
| 이상점 찾기 | `df[(df['열'] < 하한) \| (df['열'] > 상한)]` |
| 이상점 빼고 남기기 | `df[(df['열'] >= 하한) & (df['열'] <= 상한)]` |

### 찾기 / 처리하기 짝

| | 찾기 | 처리하기 |
|---|---|---|
| 결측값 | `isna()` | `dropna()`, `fillna()` |
| 중복값 | `duplicated()` | `drop_duplicates()` |
| 이상점 | `quantile()` + 조건 `\|` | 정상 범위 조건 `&`로 남기기 |

### 꼭 기억할 것 세 가지

1. **처리 함수는 전부 결과만 돌려준다.** `dropna`, `fillna`, `drop_duplicates`, 불린 인덱싱 모두 `df = ...`로 저장해야 반영된다.
2. **확인용 코드는 원본을 덮어쓰기 전에.** mask를 늦게 만들면 빈 결과가 나온다. 꼬이면 `read_csv`부터 다시.
3. **지우기 전에 왜 생겼는지 먼저 보기.** 평점 결측값은 리뷰 0개라서, 비싼 숙소는 진짜 비싸서였다.
