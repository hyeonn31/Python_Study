# cut()과 apply() 차이 정리

숫자를 몇 개의 구간으로 나누는 걸 **데이터 구간화**라고 한다. pandas에서는 `cut()`이랑 `apply()` 두 가지로 할 수 있다.
`cut()`은 구간화만을 위해 만들어진 **전용 함수**고, `apply()`는 원하는 기능을 마음대로 만들어 넣을 수 있는 **만능 함수**다.
강의에서 두 함수로 똑같은 작업(연령대 나누기)을 해 봤는데, 결과는 같은데 생긴 게 완전히 달라서 헷갈렸다. 비교해서 정리해 둔다.

---

## 시작 전에

### 데이터

환자 348명의 데이터(`patient.csv`)다.

```python
import pandas as pd
import numpy as np

patient_df = pd.read_csv('data/patient.csv')
```

| 열 | 뜻 |
|---|---|
| `age` | 나이 (최솟값 20, 최댓값 69) |
| `sex` | 성별 (Male / Female) |
| `height` | 키 (미터) |
| `weight` | 몸무게 (kg) |
| `hip`, `waist` | 엉덩이 둘레, 허리 둘레 |
| `diabetes` | 당뇨 여부 (Y / N) |

BMI도 미리 계산해 뒀다. 몸무게 ÷ 키², 소수 첫째 자리까지 반올림.

```python
patient_df['bmi'] = round(patient_df['weight'] / patient_df['height'] ** 2, 1)
```

BMI는 15.2 ~ 55.5 사이에 있다.

---

## 1. cut(): 구간 나누기 전용

### 기본 모양

나이를 10살 단위 연령대로 나눠 봤다.

```python
age_group = pd.cut(patient_df['age'],
                   bins=[10, 20, 30, 40, 50, 60, 70],
                   right=False,
                   labels=['10s', '20s', '30s', '40s', '50s', '60s'])
```

넣는 건 세 가지다.

- **첫 번째**: 나눌 데이터 (`patient_df['age']`)
- **`bins`**: 구간의 경계값 목록
- **`labels`**: 각 구간에 붙일 이름표

열에 붙여 쓰는 함수가 아니라서 `patient_df['age'].cut()`이 아니라 **`pd.cut()`**으로 쓴다. 처음에 이거 헷갈렸다.

### bins랑 labels 개수

경계값이 7개면 그 사이 구간은 **6개**다. 그래서 `labels`도 6개. 개수가 안 맞으면 에러가 난다.

```
   10 ── 20 ── 30 ── 40 ── 50 ── 60 ── 70
     10s   20s   30s   40s   50s   60s
```

### right=False

경계에 **딱 걸친 값**을 어느 쪽에 넣을지 정하는 옵션이다. 30살은 20대일까 30대일까?

| `right` | 구간 모양 | 30살은 |
|---|---|---|
| `True` (기본값) | `(20, 30]` → 오른쪽 끝 포함 | `20s` |
| `False` | `[20, 30)` → 왼쪽 끝 포함 | `30s` |

연령대는 "20 **이상** 30 **미만**"이니까 `right=False`.
이거 빼먹어도 **에러가 안 난다.** 경계에 있는 사람들만 조용히 엉뚱한 구간에 들어가서 눈치채기 어렵다.

### 마지막 경계값은 최댓값보다 크게

`right=False`면 오른쪽 끝은 포함이 안 되는데, **마지막 구간도 마찬가지**다.

BMI 실습에서 이걸로 고민했다. BMI 최댓값이 55.5인데 마지막 경계를 `max()`로 하면 마지막 구간이 `[30, 55.5)`가 돼서, 55.5인 사람이 어디에도 안 들어가고 `NaN`이 된다. 실제로 해 보니 1명이 `NaN`이 나왔다.
그래서 최댓값에 1을 더해서 끝을 잡았다.

```python
bmi_max = patient_df['bmi'].max() + 1   # 56.5

pd.cut(patient_df['bmi'],
       bins=[0, 18.5, 25, 30, bmi_max],
       right=False,
       labels=['under', 'healthy', 'over', 'obese'])
```

`np.inf`(무한대)를 쓰면 데이터가 바뀌어도 신경 쓸 필요가 없다.

```python
bins=[0, 18.5, 25, 30, np.inf]
```

```
obese      138
healthy    102
over       101
under        7
```

BMI 데이터에는 정확히 18.5, 25.0, 30.0인 사람이 8명이나 있어서, `right=False`를 빼먹으면 이 8명이 한 칸씩 아래 등급으로 들어간다.

결과 타입은 `category`(범주형)다. 정해진 몇 개 값 중 하나만 들어가는 타입.

## 2. apply() 기본 사용법

### 함수를 받아서 값마다 적용

`apply()`는 **다른 함수를 아규먼트로** 받는다. 이름 그대로 '적용하다'라서, Series에 있는 **값 하나하나에** 받은 함수를 적용해 준다.

강의 예제:

```python
df = pd.DataFrame([[1, 9], [4, 16]], columns=['column1', 'column2'])
```

```
   column1  column2
0        1        9
1        4       16
```

`column2`의 9와 16의 제곱근을 구한다. numpy의 `sqrt()`는 숫자 하나를 받아서 제곱근을 돌려준다.

```python
np.sqrt(9)   # 3.0

df['column2'].apply(np.sqrt)
```

```
0    3.0
1    4.0
Name: column2, dtype: float64
```

9에 한 번, 16에 한 번, `sqrt()`를 하나씩 적용한 것.

### 함수 이름 뒤에 괄호 X

```python
df['column2'].apply(np.sqrt)     # O
df['column2'].apply(np.sqrt())   # X → 에러
```

함수를 넘겨줄 때는 **이름까지만** 쓴다.
괄호를 붙이면 그 자리에서 함수가 바로 실행돼 버린다. 지금 실행하는 게 아니라 "이 함수를 값마다 적용해 줘" 하고 **맡기는** 거라서 이름만 넘긴다.

---

## 3. apply()로 구간화하기

1번에서 `cut()`으로 한 연령대 분류를 `apply()`로 똑같이 해 봤다. 넣을 함수는 직접 만든다.

```python
def group_age(x):
    if x >= 10 and x < 20:
        return '10s'
    elif x >= 20 and x < 30:
        return '20s'
    elif x >= 30 and x < 40:
        return '30s'
    elif x >= 40 and x < 50:
        return '40s'
    elif x >= 50 and x < 60:
        return '50s'
    else:
        return '60s'

patient_df['age_group'] = patient_df['age'].apply(group_age)
```

1. 나이 **하나**(`x`)를 받아서 if문으로 구간을 확인하고, 연령대 이름 **하나**를 돌려주는 함수를 만든다.
2. `apply(group_age)`로 넘긴다. 여기도 괄호 없이 이름만.
3. 결과를 `age_group` 열에 저장한다.

```
20s    63
30s    77
40s    83
50s    65
60s    60
```

`cut()` 결과랑 비교해 보니 348명 **전부 똑같았다.**

### 경계값이 코드에 그대로 보인다

`apply()`는 `right=False`를 고민할 필요가 없다. "20 이상 30 미만"이 `x >= 20 and x < 30`으로 그대로 보이니까.
마지막은 `else`라서 최댓값 때문에 `NaN`이 생길 걱정도 없다.

`elif`는 위 조건이 전부 거짓일 때만 확인하니까, `x >= 20` 부분은 빼고 `elif x < 30:`만 써도 결과는 같다.

### 그래서 cut()이랑 뭐가 다른데

| | `cut()` | `apply()` |
|---|---|---|
| 하는 일 | 숫자를 **구간으로 나누기** | 값마다 **원하는 함수 적용** |
| 쓰는 곳 | 숫자 구간화 **전용** | 뭐든지 (만능) |
| 코드 | 경계값 + 이름표 목록이면 끝 | 함수를 직접 만들어야 함 |
| 경계값 처리 | `right` 옵션 | if문 조건에 그대로 보임 |
| 결과 타입 | `category` | 함수가 돌려준 값 그대로 (`str` 등) |

구간화만 할 거면 `cut()`이 **훨씬 짧다.** 대신 구간화가 아닌 다른 가공은 못 한다.
`apply()`는 그때그때 상황에 맞는 함수만 만들어 넣으면 뭐든 할 수 있다.

## 4. 람다 함수 + apply()

### 람다 함수

`def`로 따로 만들지 않고, 다른 함수 안에서 바로 만들어 쓰는 한 줄짜리 함수다. 이름이 없어서 **익명 함수**라고도 한다.

```python
def multiply_two(x):
    return 2 * x

lambda x: 2 * x   # 위랑 같은 함수
```

`lambda 파라미터: 리턴할 값` 모양.
다시 쓸 일 없는 간단한 함수면 람다로 만드는 게 편하다.

### apply()에 넣기

`height`(미터)를 인치로 바꾸는 예제. 1미터 ≈ 39.370079인치.

```python
patient_df['height'].apply(lambda x: 39.370079 * x)
```

키 값이 하나씩 `x`에 들어가서 곱해진다. 1.75m → 68.9인치.

**근데 이건 사실 `apply()`를 쓸 필요가 없다.** 열에 바로 곱하면 된다.

```python
patient_df['height'] * 39.370079
```

pandas는 열 전체를 한 번에 계산하게 만들어져 있어서 이게 더 짧고 **훨씬 빠르다.** `apply()`는 값을 하나씩 꺼내서 함수를 348번 돌리는 거라 느리다.
BMI 계산, 정규화처럼 계산식 하나로 끝나는 건 그냥 바로 계산하기.

### if문이랑 같이 쓰기

람다는 if문이랑 같이 쓸 때 쓸모가 많다. BMI가 30 넘으면 `Y`, 아니면 `N`.

```python
patient_df['bmi'].apply(lambda x: 'Y' if x > 30 else 'N')
```

모양이 낯설어서 이렇게 끊어 읽었다.

```
lambda x:  'Y'        if x > 30    else 'N'
           참일 때     조건          거짓일 때
```

**경계값 주의!** 강의 코드는 `x > 30`(30 **초과**)인데, 비만 기준은 보통 "30 **이상**"이다.
이 데이터에 BMI가 정확히 30.0인 사람이 **5명** 있어서, `> 30`이면 133명, `>= 30`이면 138명으로 결과가 달라진다. 1번 `cut()` 결과(obese 138명)랑 맞추려면 `>=`를 써야 한다.
"이상"이면 `>=`, "초과"면 `>`.

### 파라미터가 여러 개인 함수

BMI가 **두 값 사이**에 있으면 `Y`를 돌려주는 함수. 구간을 그때그때 바꿀 수 있게 파라미터로 받는다.

```python
def isin_interval(x, n_lower, n_upper):
    if n_lower <= x < n_upper:
        return 'Y'
    else:
        return 'N'
```

문제는 `apply()`는 값을 **하나만** 넘겨주는데, 이 함수는 파라미터가 **세 개**라는 거다. 그래서 `apply(isin_interval)`로는 안 되고 람다로 한 번 감싼다.

```python
patient_df['bmi'].apply(lambda x: isin_interval(x, 18.5, 25))   # 정상: 18.5 이상 25 미만
patient_df['bmi'].apply(lambda x: isin_interval(x, 25, 30))     # 과체중: 25 이상 30 미만
```

1. `apply()`가 BMI 값 하나를 람다의 `x`에 넣는다.
2. 람다가 그 `x`에 18.5, 25를 붙여서 `isin_interval()`을 부른다.

숫자만 바꾸면 다른 구간도 바로 구할 수 있다. 정상 102명, 과체중 101명으로 `cut()` 결과랑 똑같다.

## 5. apply()만 할 수 있는 것

`cut()`은 **숫자 하나를 구간으로 나누는 것**만 한다. 나머지는 다 `apply()` 몫이다.

### 문자 데이터

```python
patient_df['sex'].apply(lambda x: 'M' if x == 'Male' else 'F')
```

`cut()`은 숫자 전용이라 안 된다.

### 여러 열을 같이 보기 — axis=1

"BMI 30 이상**이고** 나이 50 이상이면 `Y`"처럼 **열 두 개 이상**을 같이 봐야 할 때.

```python
patient_df.apply(lambda row: 'Y' if row['bmi'] >= 30 and row['age'] >= 50 else 'N', axis=1)
```

- 열 하나가 아니라 **표 전체**(`patient_df`)에 `apply()`를 건다.
- `axis=1`이면 함수에 **행 하나가 통째로** 들어온다. 그래서 `row['bmi']`, `row['age']`로 꺼내 쓸 수 있다.
- 결과: Y 49명.

여기서도 `axis=1`은 "왼 → 오른쪽으로 훑어서 **행마다** 결과 하나"다. (12번 결측값 단원의 `any(axis=1)`이랑 같은 원리)

함수 안에서는 `&` 말고 `and`를 쓴다. 값 하나하나를 비교하는 평범한 파이썬 코드라서. 불린 인덱싱처럼 Series 전체를 비교할 때만 `&`.

## 6. 언제 뭘 쓰나

| 상황 | 쓸 것 |
|---|---|
| 계산식 하나로 끝남 (단위 변환, BMI, 정규화) | **바로 계산** `df['a'] * 39.37` |
| 숫자 → 구간 (연령대, 비만도, 점수 등급) | **`cut()`** |
| 문자 데이터 가공 | **`apply()`** |
| 여러 열을 같이 보고 판단 | **`apply(axis=1)`** |
| 구간이 아닌 복잡한 규칙 | **`apply()`** + 직접 만든 함수 |

판단 순서

1. 열끼리 바로 계산되나? → 그냥 계산
2. 숫자를 구간으로 나누는 건가? → `cut()`
3. 둘 다 아니면 → `apply()`

## 실습하면서 틀린 것

```python
labels=['under','healthy",'over','dbese']
```

```
SyntaxError: unterminated string literal
```

`'healthy"`를 작은따옴표로 열고 큰따옴표로 닫았다. 파이썬은 `'`로 연 문자열이 다음 `'`까지 이어진다고 봐서, 줄 끝까지 안 닫혔다는 에러가 난다.
`'dbese'`도 `'obese'` 오타. 채점은 이름표 글자까지 비교하니까 조심.

## 한눈에 보기

```python
# cut(): 경계값 + 이름표
pd.cut(df['열'], bins=[경계1, 경계2, ...], right=False, labels=[이름1, ...])

# apply(): 값 하나씩 함수 적용 (괄호 없이 이름만)
df['열'].apply(함수이름)

# apply() + 람다
df['열'].apply(lambda x: 'Y' if x >= 30 else 'N')

# 파라미터 여러 개인 함수는 람다로 감싸기
df['열'].apply(lambda x: 함수(x, 값1, 값2))

# 여러 열을 같이 볼 땐 표 전체에 axis=1
df.apply(lambda row: ... row['열1'] ... row['열2'] ..., axis=1)
```

### 꼭 기억할 것

1. **`cut()`은 구간화 전용, `apply()`는 만능.** 구간화는 `cut()`이 더 짧다.
2. **`apply()`에는 함수 이름만.** 괄호 붙이지 않기.
3. **경계값 항상 확인.** `cut()`은 `right=False`랑 마지막 경계값, 람다는 `>`랑 `>=`.
4. **바로 계산되면 `apply()` 쓰지 않기.** 직접 계산이 더 짧고 빠르다.
